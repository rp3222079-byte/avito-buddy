# Бадди · Avito Start

AI-помощник для адаптации стажёров Авито. Стажёр получает утренний брифинг, смотрит задачи Jira и готовит заявки на доступ. Наставник видит прогресс стажёров, разбирает блокеры и может перейти в чат из строки стажёра.

Frontend использует React, TypeScript и Vite. В режиме `mock` приложение работает на локальных демоданных. В режиме `real` браузер обращается к Go API, который передаёт запросы чата в FastAPI. AI-сервис использует LLM и поиск по базе знаний через RAG.

## Быстрый запуск в mock-режиме

Из корня репозитория запусти frontend через Docker Compose. По умолчанию `VITE_API_MODE=mock`. Если раньше включал `real` в `.env` или терминале, верни значение `mock` перед сборкой.

```sh
docker compose up --build frontend
```

Открой [127.0.0.1:5173](http://127.0.0.1:5173). Для этого запуска достаточно frontend, ключи API и модель не нужны.

Для разработки без Docker нужен Node.js 22.12+ и npm.

```sh
npm ci
npm run dev
```

Открой адрес, который выведет Vite.

## Демо за две минуты в mock-режиме

1. Выбери «Стажёр» и нажми «Утренний брифинг» → «Открыть задачи». Раскрой задачу Jira, посмотри текущий этап и нажми «Вернуться к диалогу». Переписка сохранится.
2. Нажми «Доступ к Jira». В черновике можно изменить основание или отменить заявку. После «Отправить заявку» появится номер `REQ-042` и статус ожидания согласования.
3. Переключись на «Наставник». Сразу откроется дашборд. Найди заявку и нажми «Согласовать в демо». Вернись в роль стажёра и проверь, что доступ выдан в демо и начислено 120 XP.
4. На дашборде наставника раскрой «Застрял», открой этапы задачи и «Среднее время» за всё время. Включи «Только с флагами» и нажми «Обновить из Jira» рядом с рейтингом. Фильтр сохранится.

В mock-режиме история стажёра, заявка и прогресс сохраняются в браузере. В меню профиля есть «Начать демо заново». В «Помощи» можно включить ошибку следующей отправки заявки или прервать следующий ответ Бадди. После обрыва нажми «Повторить отправку». В истории останется один экземпляр вопроса.

## Запуск с Go API и LLM

Модель выбирается через `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`. Подходит любой провайдер, у которого выбранная модель поддерживает OpenAI Chat Completions, потоковые ответы и вызов инструментов. Для API с другим протоколом нужен совместимый шлюз или отдельный адаптер.

1. Скопируй [`.env.example`](.env.example) в `.env`. Задай `VITE_API_MODE=real`, оставь `DEMO_MODE=true` для тестовых сессий и установи случайные значения `INTERNAL_TOKEN` и `REQUEST_CONTEXT_SECRET`.
2. Для внешнего провайдера укажи в `.env` базовый URL API без суффикса `/chat/completions`, ключ и идентификатор модели. Пример для BotHub.

   ```dotenv
   LLM_BASE_URL=https://openai.bothub.chat/v1
   LLM_API_KEY=
   LLM_MODEL=gemini-2.5-flash-lite
   ```

   Выбери модель из каталога, доступного твоему ключу. Укажи ключ в локальном `.env` или передай `LLM_API_KEY` через окружение терминала. Compose передаёт его только AI-сервису. [Документация BotHub](https://bothub.chat/api/documentation/ru)

   Для своей локальной модели запусти ее и подставь её тег в команду и в `LLM_MODEL`. Она должна принимать запросы из контейнера AI-сервиса по адресу ниже. Ключ для этого локального адреса можно оставить пустым.
Пример на локальной Ollama:
   ```dotenv
   LLM_BASE_URL=http://host.docker.internal:11434/v1/
   LLM_API_KEY=
   LLM_MODEL=qwen3:8b
   ```

   Если своя модель уже развёрнута на сервере, укажи адрес её OpenAI-совместимого API, доступный из контейнера, ключ и точный идентификатор модели. Внутри контейнера `localhost` указывает на сам контейнер.
3. Запусти все сервисы.

   ```sh
   docker compose up --build
   ```

4. Открой [127.0.0.1:5173](http://127.0.0.1:5173) и нажми «Утренний брифинг». Рабочий поток ответа через `POST /api/chat/stream` проверяет связку браузера, Go API, AI-сервиса и провайдера.

При смене провайдера обнови три `LLM_*` параметра и запусти `docker compose up -d ai-service`. После смены `VITE_API_MODE` пересобери frontend командой `docker compose up -d --build frontend`.

Если Go API уже запущен на `127.0.0.1:8080`, задай режим перед запуском Vite в PowerShell.

```powershell
$env:VITE_API_MODE = 'real'
npm run dev
```

Проверь отмену черновика и повторное создание через «Подготовить заявку · Jira». После подтверждения сервер возвращает номер и статус «Заявка создана». Статус подтверждает регистрацию заявки. Backend использует демосессии и подготовленные данные для Jira sync, рейтинга, этапов и STUCK. Рейтинг показывает фиксированную демо-неделю `2026-W46`. После перезагрузки снятый флаг снова появится.

## Проверки перед сдачей

```sh
npm run build
npm run test:coverage
```

Сборка находится в `dist/`, её можно открыть через `npm run preview`. Покрытие сохраняется в `coverage/index.html` и `coverage/coverage-summary.json`. Минимум для строк и инструкций — 81%. В [отчёте покрытия frontend](docs/frontend-coverage.md) приведены результаты прогона, область измерения и команды воспроизведения.

В Chrome mock-сценарии обеих ролей проверены на 320, 390, 768 и 1440 px. В real-режиме с BotHub и `gemini-2.5-flash-lite` проверены потоковый брифинг, загрузка задач, отмена и подтверждение заявки, Jira sync и снятие флага. Чек-лист для повторного прогона есть в [плане сдачи](docs/frontend-delivery-plan.md). Шаблон CI находится в [`docs/ci.yml.example`](docs/ci.yml.example).

## Структура

- [`src/`](src/) — интерфейс стажёра и наставника, чат, API-адаптеры и тесты.
- [`backend/`](backend/) — Go API, демосессии и роли, Redis и PostgreSQL.
- [`ai-service/`](ai-service/) — чат, вызов LLM и инструментов. [Запуск AI-сервиса](ai-service/README.md)
- [`rag-service/`](rag-service/) — поиск по базе знаний через ChromaDB.
- [`docs/openapi.yaml`](docs/openapi.yaml) — API-контракты. [Руководство по Go API](docs/backend-api.md) · [Поведение помощника](docs/behavior.md)
- [SDD сдаваемой версии](docs/sdd.md) — архитектура демо и уточнения к исходному документу.
