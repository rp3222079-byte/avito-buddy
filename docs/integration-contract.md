# Границы интеграции

Frontend пока не выполняет сетевые вызовы. Готовые endpoint и схемы зафиксированы в `docs/openapi.yaml`.

## Go Backend → AI-service

- `POST /api/chat` принимает `{"message":"..."}` и проксирует JSON-ответ.
- `POST /api/chat/stream` принимает то же тело и проксирует SSE-события без буферизации.
- Go Backend получает `user_id` и `role` из cookie-сессии и самостоятельно устанавливает доверенные заголовки `X-User-ID` и `X-User-Role` для AI-service.

## AI-service → Go Backend

Вызовы инструментов должны передавать `X-Internal-Token` вместе с `X-User-ID` и `X-User-Role`. Общий токен задаётся через `INTERNAL_TOKEN`. Без него Go Backend игнорирует identity-заголовки и возвращает `401`.

## AI-service → RAG

`POST http://rag-service:8001/rag/search` принимает `query` и возвращает до четырёх элементов с полями `text`, `source`, `score`, `chunk_id`, а также общий признак `confident`.

## Данные, которые уже использует интерфейс

- Профиль: отображаемое имя, команда, роль, наставник. Сейчас фиксированные демоданные.
- Квест: `id`, `title`, `description`, награда и статус `available | pending | done`.
- Сообщение: `id`, `role`, `text`, необязательная ссылка на источник и карточка действия.
- Заявка: `id`, `resource`, `reason`, статус `draft | pending | approved`.
- Ответы с источниками: заголовок, текст, идентификатор документа; сейчас статические статьи.

## Операции для будущего адаптера

1. Получить профиль и состояние онбординга.
2. Отправить сообщение; принять поток текста, источники и предложенное действие.
3. Подтвердить действие с явными проверенными параметрами.
4. Получить сохранённый результат операции и актуальный статус заявки.
5. Отметить прочитанную инструкцию и получить обновлённый прогресс.

Для подтверждения заявки нужен ключ идемпотентности. Сервер должен проверять реальные scopes и доступность документов, сохранять результат и возвращать статус. Переданные браузером роль, XP и completed нельзя считать доверенными. При реальной интеграции кнопку демосогласования и локальный переключатель ошибки следует убрать, а опыт рассчитывать по подтверждённым сервером событиям.

Текущий reducer в `src/model.ts` задаёт ожидаемые состояния. Таймеры в `src/App.tsx` — места замены на асинхронный адаптер. Механика комнат и визуальные компоненты могут использовать те же состояния после подключения API.
