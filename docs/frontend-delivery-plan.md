# План сдачи Avito Start

Frontend в Compose, cookie-сессия, SSE, черновики заявок, дашборд и раздел «Мои задачи» реализованы. Для приёмки осталось поднять стек с выбранной LLM и повторить сквозные сценарии через Go API. Исторический срез и исходные промпты сохранены ниже.

Срез на 16.11.2026. [GitHub main на 9d4efcc](https://github.com/rp3222079-byte/avito-buddy/tree/9d4efccfd58b7a36f8e13dc7bb911a167c725bc5). Локальный HEAD — `1d71b7a`, отстаёт на 14 коммитов. Перед первой задачей перенеси локальные правки документации на актуальный main и проверь diff. Docker/Go и сквозной запуск при сверке не проверялись.

## План

| Очередь | Ответственный | Результат и приёмка |
| --- | --- | --- |
| 1 · P0 | Роман + владелец Compose | Frontend Dockerfile, сборка Vite и раздача SPA. Same-origin proxy для API и корневых маршрутов, SSE приходит до завершения ответа. `docker compose up --build` из чистого клона открывает UI по URL из README. |
| 2 · P1, параллельно с 1 | Владельцы AI и Compose | Определить профиль для полноценного запуска с моделью и отдельно обозначенный резерв для демо без LLM. Проверка полноценного пути — фактический запрос в чат. Согласовать конфиг ключа/модели и общие секреты сервисов. |
| 3 · P1 | Роман + владелец Go-контрактов | Demo session до защищённых запросов, SSE на `/api/chat/stream`, черновик и серверное подтверждение/отмена. При смене роли запросы идут от текущей сессии. При обрыве видна повторная попытка, повтор подтверждения не создаёт второй тикет. |
| 4 · P1 по правкам 13.11 | Роман | Подключить имеющиеся mock-ручки Go. Jira sync → обновление рейтинга. Топ-3 выделен, топ-1 с короной, топ-5 виден и отмечен медалью в профиле. На задаче 4 этапа, у наставника таблица среднего времени и STUCK-фильтр. |
| 5 · Сдача | Роман + Мадина | Чистый запуск и прогон сценариев. Скрин/запись и покрытие frontend, команды и результаты проверки. Сверка README, SDD и презентации с работающим демо. |

Docs и код GitHub имеют приоритет для wire-форматов. В PDF пример недели W45, фактический мок W46. В примере этапов `current_stage` расходится с последним переходом. UI берёт `week` и `current_stage` из ответа. В PDF встречается `GET /mentor/{id}/interns`, в Go рабочий путь — `GET /api/mentor/interns`. Ручной Jira sync возвращает mock-результат. Расчёт очков, cron, реальная Jira через MCP, автоснятие флагов и история этапов относятся к следующей версии. Доступ из презентации формулировать как «заявка отправлена», если API подтверждает только создание. Цифры −1,5 часа, ×2 и 68→90% обозначить как цели/гипотезы до проверки источников. Слайд с ролями команды расходится с ранним AGENTS по Данилу/Степану. Подтвердить владельцев с Мадиной.

## Промпты для Codex

Запускай каждый блок отдельной задачей. Начни с актуального main и проверь `git status`. В отчёте по каждой задаче нужны затронутые файлы, фактические команды и результаты, оставшиеся блокеры.

### 1. Frontend в Docker Compose

```text
В avito-buddy добавь production-сборку React/Vite в Compose и обнови инструкцию запуска. Перед правками прочитай AGENTS.md, docker-compose.yml, .dockerignore, package.json, vite.config.ts и Go router. Собери UI через npm ci и npm run build. Раздавай dist с SPA fallback. Передавай VITE_API_MODE на этапе сборки. Настрой same-origin proxy на backend:8080 для /api, /sync/jira, /scoreboard, /tasks/<id>/stages, /interns/<id>/metrics и /flags. Сохрани Set-Cookie, методы, query и поток SSE без буферизации. Учитывай, что dev-прокси Vite тоже нужен для этих API-путей и не должен перехватывать совпадающие SPA-маршруты. Секреты остаются на уровне сервисов. Проверь docker compose config, запуск из чистого клона, загрузку UI и deep link, передачу cookie и ранний SSE-фрагмент после задач 2–3. Если что-то нельзя запустить, перечисли проверки со статусом.
```

### 2. LLM для демо

```text
Задача для владельца AI/Compose. Прочитай .env.example, docker-compose.yml, ai-service/README.md и конфиг FastAPI. Текущий дефолт требует Ollama с qwen3:8b на хосте. Подготовь воспроизводимый запуск с выбранным командой OpenAI-compatible провайдером или Ollama, включая настройку модели, ключа и prerequisites. Проверь доступность модели реальным запросом через Go SSE. Покажи понятный сбой при её недоступности. Для прогона без LLM документируй существующий явно обозначенный frontend mock. Согласуй единые INTERNAL_TOKEN и REQUEST_CONTEXT_SECRET для использующих их сервисов, передавай секреты через окружение. Укажи отдельно проверенные ручные шаги и зависимости вроде загрузки модели.
```

### 3. Сессия, SSE и заявка

```text
Интегрируй real-режим UI avito-buddy с существующим Go API. Прочитай docs/openapi.yaml, docs/backend-api.md, backend/internal/api/router.go и тесты, затем src/api.ts, src/sse.ts, src/App.tsx и компоненты заявки. Сохрани frontend mock и текущий дизайн. Создавай и заверши demo cookie-сессию по фактическому контракту, дождись её до запросов, обрабатывай смену роли, 401 и 403. Установи дефолт /api/chat/stream, сохрани VITE_CHAT_PATH override и обработку token/done/error. Сверь реальные payload actions с AI и Go. Подключи existing pending_id либо создай черновик по контракту. Подтверждай или отменяй только по действию пользователя; показывай канонический ответ Go. Проверь истёкший черновик, двойной клик, отказ API, обрыв SSE и повтор. Добавь регрессионные тесты на важные переходы и запусти сборку и frontend-тесты.
```

### 4. Рейтинг, этапы, метрики и STUCK

```text
Выполни frontend-пункты правок от 13.11 в avito-buddy. Источники wire-контрактов — docs/openapi.yaml, docs/backend-mvp-13-11.md и Go handlers. Используй текущие MentorDashboard, model, api, визуальные токены и маскота. POST /sync/jira показывает pending до ответа, затем обновляет /scoreboard и выводит время успешного обновления без искусственной задержки. Рейтинг использует place/is_top5, топ-3 выделен, топ-1 с короной, медаль видна в профиле участника топ-5. На задаче отобрази четыре этапа с current_stage и галочками пройденных. Для /interns/{id}/metrics выведи таблицу: положительное отклонение красным, отрицательное зелёным. Для /flags покажи активные бейджи на стажёре и задаче, reason по нажатию, фильтр и resolve. После успеха PATCH скрывай ID в state, ошибка оставляет бейдж. После перезагрузки мок снова показывает флаг. Проверь отсутствие данных/404, мобильный экран и управление с клавиатуры. Сохрани mock/real адаптеры и существующий UI; этапы и неделя берутся из ответа API. Запусти сборку и frontend-тесты.
```

### 5. Приёмка жюри

```text
Проверь avito-buddy из чистого checkout по инструкции для жюри. Выполни docker compose config и docker compose up --build. Прогони четыре пути: утренний брифинг и задачи; вопрос к Бадди с источником и SSE; заявка с отменой или подтверждением, каноническим статусом и отсутствием дубля; дашборд с Jira sync, рейтингом, этапами, метриками и STUCK. Повтори проверки API под обеими ролями и при недоступной модели. Запусти npm run build, npm run test:coverage, go test ./... из backend и тесты Python согласно README. Укажи реальные показатели и охват моков. Сверь README, SDD и слайды с наблюдаемым поведением. Верни блокеры с шагами проверки, результаты и краткий сценарий демо. Не пушь и не меняй внешние сервисы в рамках приёмки.
```
