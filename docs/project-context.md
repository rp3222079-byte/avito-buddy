# Контекст проекта и требования трека

Зафиксировано по обсуждению кейса Avito и плану команды. Это рабочая сводка; исходный кейс организаторов имеет приоритет.

## Продукт и выбранный объём

«Бадди · Avito Start» помогает стажёру пройти адаптацию: понять следующий шаг, найти инструкцию и довести организационный запрос до сохранённого результата. Выбран один глубокий сценарий получения доступа к Jira, связанный с чек-листом и базой знаний.

В репозитории есть интерактивный фронтенд-прототип и FastAPI AI-сервис. AI-сервис загружает system prompt и JSON Schema, умеет вызывать поиск по RAG и получение задач через Go API, а также отдавать поток ответа. Для работы инструментов нужны отдельно запущенные RAG и Go API. Go proxy и соединение UI с Backend ещё не подключены.

## Требования кейса и состояние

| Требование | Текущее состояние / следующий шаг |
| --- | --- |
| 3–5 сценариев или один глубокий | Реализован локальный путь заявки: черновик → проверка → отправка → ожидание → демосогласование |
| Контекст стажёра и ответы с источниками | FastAPI передаёт дату и роль из внутренних заголовков; RAG tool подключён к ожидаемому HTTP-контракту. Нужно поднять RAG-сервис и проверить реальные поля/порог уверенности |
| Действие через сервис и сохранение результата | Локальная UI-имитация и localStorage; серверная заявка и сохранение результата ещё не подключены |
| Этапы, статусы и следующий шаг | Квесты, заявка и XP; создание заявки отдельно от выдачи доступа |
| Учёт прав | Демонстрационный отказ; серверные проверки и фильтрация источников ещё не реализованы |
| SDD для AI-функций и инструментов | Prompt и JSON Schema загружаются; цикл Tool Calling реализован для `search_knowledge_base` и `get_jira_tasks`. Остальные schema-инструменты пока выключены |
| Покрытие строк прикладного кода выше 80% | Vitest и воспроизводимый отчёт npm run test:coverage; область покрытия задана в vite.config.ts |
| Отзывчивость и ошибки | Индикаторы ожидания, блокировка повтора, ошибка с повторной отправкой |
| Синтетические / обезличенные данные | Используются вымышленные личности, инструкции и заявки |

Для сдачи всего решения потребуются исходники, запуск и тестовые данные, SDD, отчёт покрытия, имитации интеграций, видео и PDF-презентация. При подключении внешней модели нужно описать сервис, модель и настройку ключа без секретов. Эти материалы ещё не все подготовлены.

Приоритеты онлайн-оценки из разбора кейса: внедряемость и интеграции 30%, UX 25%, работоспособность 20%, техническая реализация 15%, безопасность 5%, презентация 5%. Финальная защита — 60% общей оценки, онлайн — 40%.

## Команда и границы работ

- Роман — интерфейс, пользовательский путь, карточки действий и состояния.
- Даня — API, хранение, поиск, права, имитатор сервиса и Docker по обсуждённому плану.
- Степан — FastAPI AI-сервис, LLM, цикл Tool Calling, контекст диалога, брифинг и guardrails; контракты интеграций согласуются с Даней и Романом.
- Мадина — тестовые данные и объяснение сценария пользователю по обсуждённой общей точке готовности.

AI-service предоставляет `/health`, `/api/chat` и `/api/chat/stream`. Для `/api/chat` и `/api/chat/stream` Go Backend должен передавать проверенные `X-User-ID` и `X-User-Role`; локальные Swagger значения являются только демо. Ближайшая общая точка интеграции: UI → Go proxy → AI tool → результат со статусом на UI. Сверить с Даней фактические URL и поля RAG/Go API, затем подключить proxy/UI: см. integration-contract.md.

## Дизайн и игровая механика

Выбрана «Комната Бадди»: этапы слева, изометрическая комната в центре, чат справа. Пиксельный стиль выраженный, атмосфера тёплой RPG. Маскот — мудрая черепаха-проводник, второй вариант из концептов. Голубой, зелёный, фиолетовый и коралловый акценты отсылают к Avito; приглушённые оттенки не являются официальным брендбуком.

Завершение этапов приносит опыт и уровни; контрольные встречи задуманы как боссы. «Экватор» сейчас представлен только информационной карточкой. Читаемые тексты, реальные HTML-кнопки и статусы расположены поверх отдельных графических ассетов.

## Дальнейшие шаги

1. Сверить с Даней реальные адреса и форматы `/rag/search` и `/api/jira/tasks`; запустить оба сервиса и пройти эти tool calls.
2. Реализовать Go proxy: сессия → внутренние заголовки AI-service → возврат JSON/SSE фронтенду.
3. Подключить UI к Go proxy и довести вопрос по базе знаний до ответа с источником на экране.
4. Добавить хранение/обрезку контекста, fallback, tool calls для заявок/уведомлений и утренний брифинг.
5. Пройти сценарии, проверку прав, отсутствие сведений, сбой сервиса и повтор без дубликатов.
6. Подготовить презентацию и видео; зафиксировать версию к дедлайну организаторов.

Польза пока гипотеза: измерять время выполнения, успешность, обращения к наставнику и подтверждённость ответов источниками. Указанные в кейсе 40–48 часов наставника за 6 месяцев нельзя целиком считать экономией.
