# SDD · Avito Start

Срез реализации для сдачи 16.11.2026. [Исходный SDD в PDF](../Software%20Design%20Document%20%28SDD%29.pdf) описывает проектные решения и план развития. Ниже зафиксированы расхождения с работающим демо. Форматы запросов и ответов описаны в [OpenAPI](openapi.yaml).

| Раздел исходного SDD | Реализация в демо |
| --- | --- |
| Архитектура и чат, с. 1–2 | Docker Compose запускает Vite-сборку через Nginx, Go API, FastAPI и RAG с ChromaDB. Браузер создаёт демосессию через `POST /api/session`, затем отправляет чат через `POST /api/chat/stream`. Go проверяет cookie-сессию, формирует доверенный контекст и передаёт SSE-события `token`, `done` или `error`. `POST /api/chat` остаётся JSON-маршрутом. |
| Утренний брифинг, с. 3 | Сценарий запускается пользователем из чата. Автоматическое расписание относится к плану развития. |
| Заявка на доступ, с. 3–4 | Черновик `pending_action` хранится в Redis. Срок по умолчанию — 10 минут. Подтверждение через `POST /api/pending-action/confirm` создаёт или возвращает существующую заявку из PostgreSQL. Отмена выполняется через `POST /api/pending-action/cancel`. Показанный статус подтверждает регистрацию заявки. |
| Дашборд наставника, с. 3 | Рейтинг, этапы, среднее время и STUCK работают на синтетических данных. Ручной Jira sync возвращает деморезультат. Снятие флага в MVP действует до перезагрузки страницы. |
| LLM и резервный режим, с. 6 | Провайдер задаётся через `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`. Для автономного демо используется `VITE_API_MODE=mock` при сборке frontend. В режиме `real` ошибка провайдера отображается пользователю. |
